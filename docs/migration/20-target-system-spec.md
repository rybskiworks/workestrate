# 20 — Target System Specification

This is the main spec of the migrated system. It is authoritative for all
implementation work.

## 1. Tool model + XDG layout

`workestrate` is a **tool** (Rust CLI + nix flake), installed via
`nix profile install github:georgrybski/ai-workbench#workestrate` or run via
`nix run`. It is decoupled from any workspace. Configuration lives in XDG
layers.

### Directory trees

## 2. Registry file format

`~/.config/workestrate/config.toml` — tracked in the user's dotfiles repo.

### Complete annotated example

```toml
# ~/.config/workestrate/config.toml
# This file IS the user's dotfiles entry for workestrate.
# Tracked in the user's dotfiles repo (chezmoi/yadm/stow/etc.).

[settings]
# Tool-level settings (not workload-specific)
default_context = "personal"        # default layer-set name (contexts deferred; this is the layers list name)
store_dir = "~/.local/share/workestrate"  # managed clones + sources
state_dir = "~/.local/state/workestrate"  # runtime state (workspaces, var)

# ─── Registry of config repos ───────────────────────────────────────────────
# Each entry is a config repo that workestrate clones and consumes.
# `workestrate config add <url> <name>` adds an entry here.
# `workestrate config update <name>` pulls latest and updates `rev`.

[configs.personal]
url = "git@github.com:georgrybski/workestrator-config-personal.git"
ref = "main"
rev = "abc123def456789abcdef0123456789abcdef01"  # updated by `config update`

[configs.work]
url = "git@github.com:work-org/workestrator-config-team.git"
ref = "main"
rev = "789abc012def3456789abc012def456789abc012"

# ─── Ordered layers (Phase 3; Phase 1 uses single-layer or manual order) ────
# The order is the merge order: earlier layers are overridden by later ones.
# Security-aware merge applies (see §11). Contexts (named layer-sets) are
# deferred until 3+ layers exist.

layers = ["work", "personal"]

# ─── Trusted projects (project-layer config trust gating) ──────────────────
# `workestrate config trust <dir>` adds a project directory here.
# Only trusted projects' ./workestrate.toml is loaded as a project layer.
# Untrusted projects' ./workestrate.toml is ignored (security: prevents
# malicious project dirs from injecting config).

[[trusted_projects]]
path = "/home/node/Development/my-project"

[[trusted_projects]]
path = "/home/node/Development/another-project"
```

### Field reference

| Section | Field | Type | Default | Description |
|---|---|---|---|---|
| `[settings]` | `default_context` | string | `"personal"` | Default layer-set name (contexts deferred) |
| `[settings]` | `store_dir` | string | `~/.local/share/workestrate` | Managed clones + sources root |
| `[settings]` | `state_dir` | string | `~/.local/state/workestrate` | Runtime state root |
| `[configs.<name>]` | `url` | string | (required) | Git URL for the config repo |
| `[configs.<name>]` | `ref` | string | `"main"` | Git ref to track |
| `[configs.<name>]` | `rev` | string | (auto) | Pinned commit hash (updated by `config update`) |
| `layers` | (array) | array of strings | `[]` | Ordered list of config-repo names to merge |
| `[[trusted_projects]]` | `path` | string | (required) | Absolute path to a trusted project directory |

## 3. workestrate.toml full schema

The workload definition file. Lives in each config repo at
`~/.local/share/workestrate/repos/<name>/workestrate.toml`. Also at
`config.reference/workestrate.toml` (tracked, sanitized) and optionally at
`./workestrate.toml` (project layer, trust-gated).

### Top-level fields

```toml
schema_version = 1  # integer; workestrate checks compatibility on load

[secrets.<NAME>]           # secret definition (replaces secrets.rs const)
# env_var: string          # environment variable name in the host process
# hosts: [string]          # egress hosts this secret is bound to (validated against policy.rs)
# required: bool           # whether the secret must be set
# placeholder: string?     # known-bad placeholder value to reject
# source: string?          # for remapping: the source secret name
# exposed_as: string?      # for remapping: the env var name the sandbox sees

[workloads.<name>]          # workload definition
# kind: string             # "service" | "agent"
# image: table             # image spec (see §8)
# workdir: string          # guest working directory
# cpus: integer            # CPU count
# memory_mib: integer      # memory in MiB
# command: [string]        # binary + args to exec inside sandbox
# entrypoint: string       # "shell" (default; core runs /bin/sh -c "tail -f /dev/null")
# log_stop_errors: bool    # whether to log errors on stop (default: true)
# env: [[table]]           # environment variables (see below)
# secret_env: [[table]]    # host-bound secrets (see below)
# ports: [[table]]         # port mappings
# mounts: [[table]]        # mount declarations
# network: table           # network policy
# seed_files: [[table]]    # files to seed before start (replaces prepare())
# local_build: table?      # local build recipe (replaces build_path())
```

## 5. Resolution order + config discovery

```
1. Tool built-in defaults     (compiled into workestrate binary)
2. Reference config           (config.reference/workestrate.toml, shipped with tool)
3. Registry layers            (ordered `layers` in ~/.config/workestrate/config.toml;
                               each layer is a config repo at ~/.local/share/workestrate/repos/<name>/)
4. Trusted project config     (./workestrate.toml in cwd, IF cwd is in [trusted_projects])
5. Local overrides             (./workestrate.local.toml in cwd, gitignored)
6. Command-line flags         (--set key=value, if implemented)
```

### Config discovery (Rust CLI, `config.rs`)

```rust
fn discover_config() -> Result<Config> {
    // 1. WORKESTRATE_CONFIG_DIR env → single config dir (dev/testing)
    if let Ok(dir) = env::var("WORKESTRATE_CONFIG_DIR") {
        return load_single(&PathBuf::from(dir));
    }

    // 2. Load registry
    let registry = load_registry()?;  // ~/.config/workestrate/config.toml

    // 3. Load + merge layers (in order)
    let mut config = load_reference_config()?;  // config.reference/workestrate.toml
    for layer_name in &registry.layers {
        let repo_path = registry.store_dir.join("repos").join(layer_name);
        let layer_config = load_single(&repo_path)?;
        config = merge(config, layer_config)?;  // security-aware merge (§11)
    }

    // 4. Trusted project layer
    if let Ok(project_config) = load_project_layer(&registry.trusted_projects) {
        config = merge(config, project_config)?;
    }

    // 5. Local overrides
    if Path::new("workestrate.local.toml").exists() {
        let local = load_single(&PathBuf::from("workestrate.local.toml"))?;
        config = merge(config, local)?;
    }

    // 6. Validate against policy.rs allowlist
    validate_against_policy(&config)?;

    Ok(config)
}
```

### Fail-closed behavior (no config)

On a fresh install with no registry, no config repos:
- Falls back to `config.reference/workestrate.toml` (shipped with tool, tracked,
  **synthetic**).
- `workestrate plan` works (prints the synthetic reference plan, no secrets needed).
- `workestrate validate-config` works (validates the synthetic reference config).
- `workestrate pi exec` / `workestrate litellm up` REFUSE if the workload is not
  defined in the active config. With only the synthetic reference loaded, those
  names do not exist; the user must add a config repo via
  `workestrate config add <url> personal`.
- The synthetic reference uses placeholder secrets; if a workload is present it
  would be rejected by `reject_if_placeholder` (`runtime.rs:10-22`).

## 7. Source override model

### Canonical vs override

- **Canonical source**: the flake input (e.g. `github:georgrybski/pi` at
  `flake.nix:7-10`). Materialized by the devshell or by
  `workestrate source clone`.
- **Source override**: a user-cloned checkout at a different path, selected via
  `WORKESTRATE_<NAME>_BUILD` env var (existing convention, `workload.rs:80-90`).

### Store paths

```
~/.local/share/workestrate/sources/<name>/repo/    # canonical source checkout
~/.local/share/workestrate/sources/<name>/build/   # built artifact
```

### Commands

| Command | Behavior |
|---|---|
| `workestrate source clone <name> [<path>]` | Clone canonical source to store (or user path). Sets `WORKESTRATE_<NAME>_BUILD` for the session. |
| `workestrate source build <name>` | Build from the cloned source using the workload's `local_build` recipe. |
| `workestrate source list` | List all agent sources with: canonical rev, checkout path, build status, dirty status. |
| `workestrate source reset <name>` | Discard local edits; re-clone canonical source. |

### `WORKESTRATE_<NAME>_BUILD` env var

Unchanged from current behavior (`workload.rs:80-90`): NAME uppercased, `-`→`_`.
If set, the workload's `local_build.fallback` is overridden by the env value.

### Naming (ADR 0010)

- **"source override"** is the concept name.
- **`workestrate source`** is the command namespace.
- **`~/.local/share/workestrate/sources/<name>/`** is the store path.
- **`vendor`** is reserved for frozen third-party deps (microsandbox patched
  crate, ADR 0011).

## 8. Image generalization

### Three image paths

| Path | Config declaration | Core execution |
|---|---|---|
| **Registry ref** | `image = { recipe = "registry", ref = "python:3.12-slim" }` | No-op (Microsandbox pulls) |
| **Nix-layered** | `image = { recipe = "nix-layered", name = "tempest", tag = "latest", contents = [...], binary = {...}, baked_files = [...], features = [...] }` | Core's `buildWorkloadImage(spec)` generates `dockerTools.buildLayeredImage` |
| **Local build** | `local_build = { recipe = "npm-build", ... }` | Devshell or `workestrate source build` executes the recipe; result mounted at `/app` |

### baked_files rules

```toml
[[workloads.<name>.image.baked_files]]
path = "root/.config/t3mp3st/config.json"   # relative path inside image; no "/" prefix, no ".."
content = '{"defaultProvider":"local"}'      # string content only; no evaluation
```

- `path`: relative path inside the image; validated (no absolute paths, no `..`
  traversal).
- `content`: string only. No templating, no evaluation, no executable content.
- Core generates `extraCommands` shell: `mkdir -p $(dirname path) && cat > path <<'EOF' content EOF`.

### features rules

```toml
features = ["create_tmp"]
```

- Closed vocabulary in core (`nix/lib/vocabulary.nix`).
- Each feature maps to a fixed shell snippet.
- Config cannot supply arbitrary shell.

### binary recipe output → contents

The `binary` field references a build recipe. The recipe's output (a nix
derivation) is added to the image's `contents` list. The recipe handles its own
internal complexity (e.g. `bun-compile` includes `removeReferencesTo` stripping
internally, `pi-image.nix:35-50`).

## 9. Secrets model

### Per-config-repo layout

Each config repo at `~/.local/share/workestrate/repos/<name>/` contains:

```
repos/personal/
├── .env.enc          # SOPS-encrypted secrets (personal key)
├── .sops.yaml        # SOPS config (personal recipient)
├── .env.example      # generated by `workestrate generate-env-example`
└── workestrate.toml  # secrets: section defines the schema
```

### `.env.example` generation

`.env.example` is **generated** from the config `secrets:` section via
`workestrate generate-env-example`. This eliminates the three-way duplication
(`.env.example` hand-maintained, `REQUIRED_KEYS` derived by grep,
`secrets.rs` const). Post-migration, the config `secrets:` section is the
single source of truth.

`setup-secrets.sh` is updated to call `workestrate secrets-schema` to get
REQUIRED_KEYS directly from the loaded config, eliminating the `.env.example`
grep intermediate (`setup-secrets.sh:39-44`).

### SOPS multi-recipient layout (Phase 3)

For shared secrets (team + personal access):

```yaml
# ~/.local/share/workestrate/repos/personal/.sops.yaml
keys:
  - &personal age1<personal-key>
  - &team age1<team-key>
creation_rules:
  - path_regex: ^secrets/shared/.*\.enc$
    key_groups:
      - age: [*personal, *team]
  - path_regex: ^secrets/personal/.*\.enc$
    key_groups:
      - age: [*personal]
  - path_regex: ^\.env\.enc$
    key_groups:
      - age: [*personal, *team]
```

- Shared secrets encrypted to both keys (team admin can rotate/recover).
- Personal-only secrets encrypted to personal key only.
- SOPS `threshold` (Shamir N-of-M) available for high-value secrets.
- Age private keys stay outside all repos (`~/.config/sops/age/`).

## 11. Layering + merge semantics

### Ordered layers

The registry's `layers` array declares the merge order:

```toml
layers = ["work", "personal"]
```

Merge order: `config.reference/` (base) → `work` (layer 1) → `personal`
(layer 2) → trusted project (layer 3) → local (layer 4).

### Security-aware merge (ADR 0005)

| Field type | Merge rule | Rationale |
|---|---|---|
| `default_deny` | **Monotonic-true**: if any layer sets `true`, the merged result is `true`. Core per-workload entitlement for `false` (only tempest). | A less-trusted layer cannot weaken a more-trusted layer's default-deny. |
| `deny_rules` | **Additive-union** within `policy.rs` ceiling. | A less-trusted layer cannot remove a more-trusted layer's deny rule. |
| `egress_rules` | **Additive-union** within `policy.rs` ceiling + per-recipe `allowed_hosts()` scoping. | A less-trusted layer cannot remove egress rules (only add, within ceiling). |
| `secret_env` | **Additive-union** (later layers can add secrets; cannot remove). | A less-trusted layer cannot deprive a workload of required secrets. |
| All other fields (scalars, maps, lists) | **RFC 7396 JSON Merge Patch**: last-wins scalars, deep-merge maps, replace lists, `null` deletes. | Standard merge for non-security fields. |

### Provenance (`plan --show-source`)

```bash
$ workestrate plan pi --show-source
name: pi
image: workestrator-pi:latest                    [personal]
cpus: 2                                          [work]
memory_mib: 2048                                 [reference]
egress: agent_base                               [personal]
  egress: dns -> host:53                         [core]
  egress: litellm_proxy -> host:4000             [core]
  egress: https -> github.com,api.github.com:443 [core]
deny: .pi.dev                                    [personal]
```

Attribution labels: `[core]` (tool defaults), `[reference]` (config.reference/),
`[<layer-name>]` (registry layer), `[project]` (trusted project),
`[local]` (local overrides).
