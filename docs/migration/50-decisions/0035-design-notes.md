## 1. Evolution log (dated)

| Date | Step | What happened |
|------|------|---------------|
| 2026-08-16 → 09-02 | **Hardcoded allowlist flaw discovery** | `control/agentctl/src/policy.rs:4-17` `ALLOWED_EGRESS_HOSTS` identified as conflating supply-chain boundary (valid) with operator authority (invalid). Personal vendor list (`api.tempo.io` case: `tempo_buddy` blocked) leaked into public binary. Recipe check in `validation.rs:339-366` / `merge.rs:719` enforced the ceiling; adding a host required a Rust change. Decision: ceiling must be operator-configurable via runged policy, not maintainer-compiled. |
| 2026-09-02 (iteration 1) | **Ladder model iteration 1 — intersection** | First ADR draft proposed collect-and-compile ladder (`home registry > config layers > workload`) extending the secrets/mount-policy precedent (`SecretsPolicyFragment`, `mount-policy/03-hierarchy-and-precedence.md`). Entries were intersection-oriented; discussion highlighted that a higher-rung deny that is not final should still be overridable by more specific lower-rung allows when unfrozen. |
| 2026-09-02 → 09-03 (iteration 2 — user adjudication) | **User iteration 2 — both-ways allow/deny + `final` + `on_conflict` + `all` rank** | User decision: ladder supports **both `allow` and `deny` on every rung**, with `final` (fragment- or entry-level) freezing the covering set against lower rungs, `on_conflict` (`ignore`/`warn`/`fail`) per polarity table, and `all` (allow-all/deny-all) ranked **least-specific** (suffix/exact outrank `all`). Same-rung identical-coverage opposite-polarity is a hard error; cross-rung tie without `final` is deny-wins (fail-closed). Invariants #8–#16, #22 locked. |
| 2026-09-03 | **Presets dropped — inline-only** | Preset registry (`preset = "github"` → expanded domain list) was considered and rejected: a second allowlist with the same governance problem as `ALLOWED_EGRESS_HOSTS`; inline domains are explicit, grep-able, reviewable. Dropped; may revisit if vendor-bundle repetition emerges (see [`../shelved-todo.md`](../shelved-todo.md)). |
| 2026-09-03 | **SDK enforceability findings — enforcement reality** | Inspection of MSB SDK `NetworkPolicy` `Rule` model: ordered first-match-wins list `{destination Any/Cidr/Domain/DomainSuffix/Group(Host|Metadata|Loopback|Private|LinkLocal|Public), protocols set, ports PortRangeSet, action}` evaluated on smoltcp poll thread (no netfilter); DNS intercepted at gateway `53/853` (IP→hostname cache); TLS SNI peeked on first flight for domain rules. Findings forced: (a) port-scoped domain rules are fully enforceable via `e.tcp().port(n).deny_domains/allows` under both defaults when compiler orders `port-scoped denies → port-agnostic denies → allows`; legacy `prepend` helper is port-agnostic and must not be reused for port-scoped intent; (b) ingress scope maps to `DestinationGroup` peer-source groups (`Loopback`/`LinkLocal`/`Host`/`Private`/`Public`/`Metadata`/`Any`), orthogonal to `bind`; `allow_local` exact = `Loopback+LinkLocal+Host` (not `Metadata`, not `Private`); (c) domain-enforcement bypass limits documented (IP-literal + no-DNS + no-SNI, DoH-on-443, DoT-refused); (d) protocols are closed enum `Tcp`/`Udp`/`Icmpv4`/`Icmpv6`; unknown = hard error (fail-closed). These are now §5A and §3.4. |
| 2026-09-03 | **User decisions lock (this iteration)** | Seven adjudications incorporated into ADR (see Decision log §3 and Open questions §5): port-scoped domain rules APPROVED, ingress scope vocabulary APPROVED (peer-source groups + bind orthogonal), `on_conflict` per-ladder CONFIRMED, stale-schema warning P3 DEFERRED, IDNA elaboration, point-directly error-message convention, `registry.schema.json`+tombi APPROVED as committed follow-up. ADR updated to 927 lines; this design-notes file and `shelved-todo.md` created. |
| 2026-09-03 (iteration 3 — user decisions lock) | **User decision: IDNA flag-gated default-off + crate assessment** | Superseded prior IDNA rejected-v1: now ` [policy.idna] mode = "reject"`(default, hard error with codepoint + punycode hint) \| `"uts46"` (strict `idna::domain_to_ascii_strict` with `STD3`/`Check`/`Verify`, nontransitional/Bidi/Joiner) + `unicode-security` skeleton/mixed-script WARNINGs; ladder `built-in reject → home → layers → workload` with `final` sealing (§3.5). Crate assessment: `idna` `1.1.0` already transitive in `Cargo.lock` (`url`/`hickory-proto`), promote to direct `idna = "1.1"` + `unicode-security = "0.1"` (`0.1.2` on crates.io); fork `microsandbox-*` patch unaffected; cost ~200-300 LOC validation + ~100 LOC compiler wiring + tests (§11.1 §12.1 vectors). ADR §3.5 new, §5#17 rewritten, §12.1 rewritten (substantive), §11.1 vectors expanded, §12 table updated, §13 risk rewritten; shelved entry 5 now DESIGNED implement-in-v1. |
| 2026-09-03 (iteration 3 — user decisions lock) | **User decision: outright removal (no deprecation windows) pre-public** | Superseded prior "pattern noted, n/a now": removed vocabulary is **removed outright** — no compat aliases, no `warn`-then-`remove`, no dual-stack. ## 2. Assumptions held

| # | Assumption | Status | Why held |
|---|------------|--------|----------|
| A1 | SDK builder is expressive enough for port-scoped domain policy | **Validated** — `e.tcp().port(443).deny_domains([...])` / `.allow_domains(...)` is ordered first-match-wins and supports port-agnostic (`PortRangeSet::Any`) and port-scoped (`port(n)`) denies | Code inspection of SDK `Rule` + builder (see ADR §5A.4). Both defaults work because default is only the fallback after rules. |
| A2 | First-match-wins ordering is fully controllable by the compiler | **Validated** — the compiler emits ordered builder calls (port-scoped denies → port-agnostic denies → allows, within specificity). The legacy prepend helper (port-agnostic) is the only ordering foot-gun and is avoided. | ADR §5A.4 + §6 emit order. |
| A3 | Default-deny is preserved | **Held** — `[network.defaults] egress = "deny"` (and `ingress = "deny"`) plus `entitlements` gating is unchanged; the hierarchy never bypasses `deny` (invariant #13). `allow` default still evaluates every rule; the default is fallback, not short-circuit. | Invariant #13, #21; §10; §5A.1 allow-default note. |
| A4 | Personal/duelbits configs are operator-owned (tool-home / config-repo / workload rungs) | **Held** — the operator owns `~/.microsandbox`, `WORKESTRATE_HOME`, and host firewall. `home registry` ( `<home>/config.toml` `Registry.policy`) is highest authority; config layers are middle; workload is lowest. This justifies the rung order and `final` semantics. | §2.1 flaw, §3.1 rungs. |
| A5 | Tombi strict lint + `generate_schema_pair` cover most schema drift | **Held** — `tombi strict` (schemars-derived `schemas/workestrate.schema.json`) catches most drift; `validate-config` staleness warning on stale consumer copies is P3 and is deferred to avoid `validate-config` mutation scope creep. | `docs/runtime-provisioning.md` schema flow; ADR §12 shelved row; [`../shelved-todo.md`](../shelved-todo.md). |
| A6 | Ingress domain rules cannot be enforced (no SNI for peers) | **Held** — ingress evaluator sees only peer IP + port; no TLS SNI; reverse-DNS is not a policy primitive. Ingress domain entries are a hard validation error. | §3.4.3. |
| A7 | Hard cutover (no aliases, no dual-stack) is acceptable pre-release | **Held** — ADR 0031 precedent; `validate-config` fails closed on removed vocabulary, and §9.4 messages cite ADR 0035 directly. | §5 #20, §9.4, §10. |
| A8 | No deprecation windows pre-public — outright removal + ADR-citing errors + intent tests suffice; versions resettable | **Held** — user decision 2026-09-03; hard cutover with actionable errors and §11 golden/Provenance tests is the drift guard; deprecation windows rejected pre-public, revisit only post-public-adoption | §9.4, shelved entry 8 |

## 3. Decision log (one-liner rationale per decision, with date)

| Date | Decision | Rationale (one-liner) |
|------|----------|-----------------------|
| 2026-09-03 | **Presets dropped — inline-only** | Avoids a second governed allowlist; inline `[[policy.egress.allow.domain]]` is explicit, reviewable, grep-able. Revisit only if repetition proves ergonomic. |
| 2026-09-03 | **Recipes hard-cutover — deleted, no compat aliases** | Pre-release, no migration debt; `deny_unknown_fields` + §9.4 `see ADR 0035` messages make the rewrite self-documenting; ADR 0031 precedent. |
| 2026-09-03 | **Port axis asymmetry — allow port REQUIRED, deny port optional (= any-port)** | Allow without port hides a default to 443 (rejected); deny without port intentionally broad = fail-closed (broad deny is safe, narrow is a bypass); more expressive than old port-agnostic-only deny; SDK can enforce both via ordered builder. |
| 2026-09-03 | **Ingress scope vocabulary — peer-source groups + bind orthogonal** | SDK `DestinationGroup` is peer-source, not bind — `loopback`/`local`/`private`/`public`/`any` map exactly to SDK groups; `local` = `allow_local` (`Loopback+LinkLocal+Host`, not `Metadata`, not `Private`); `bind` (`PublishedPort.host_bind`) is orthogonal; reachability = `bind ∧ policy ∧ port`. |
| 2026-09-03 | **`on_conflict` per-ladder granular (egress vs ingress separate, overridable, `final` seals)** | Egress and ingress are independent axes; a single top-level `on_conflict` would conflate them; per-polarity-table with `final` sealing is reviewable and matches the ladder (`home final` seals lower rungs' choice on that ladder only). CONFIRMED, already in ADR — wording made unambiguous in §5 #14 + §8. |
| 2026-09-03 | **`final` semantics — symmetric on both polarities, `final` seals `on_conflict`** | Operator authority is rung height, not polarity; `deny-final` and `allow-final` both obey invariant #11; `final` also seals the rung's `on_conflict` choice. Mount-policy trust-gate for allow-final does not transfer (deny already wins ties via #9). |
| 2026-09-03 | **IDNA / UTS46 rejected v1** | Core vocab is ASCII (zero current need); IDNA is a versioned supply-chain of Unicode tables (mapping/NFKC/contextual/Bidi/deviation); homograph in a policy context = authorization bypass (`gіthub.com` vs `github.com`); even correct `ToASCII` needs UTS39 confusable linter — deferred behind explicit flag; v1 hard-errors with punycode hint. **(superseded 2026-09-03 by flag-gated design — this row retained for history; see new flag-gated row below)** |
| 2026-09-03 | **IDNA flag-gated default-off (`[policy.idna] mode = "reject" \| "uts46"` ladder with `final`)** | Safe-by-default `reject` (hard error with codepoint + punycode hint); explicit opt-in runs `idna` strict `ToASCII` + `unicode-security` skeleton/mixed-script warnings; ladder same as `on_conflict` (`built-in reject → home → layers → workload`, `final` seals); crates already in lock (`idna` `1.1`) + `unicode-security` `0.1.2`; implement in v1 engine phase (§3.5 §12.1) |
| 2026-09-03 | **No deprecation windows — outright removal (pre-public)** | Versions resettable, hard cutover with ADR-citing errors + intent tests as drift guard; deprecation windows rejected pre-public, revisit only post-public-adoption (§9.4, shelved entry 8) |
| 2026-09-03 | **Trust-gating dropped for `final-allow` (no operator-only gate)** | Mount-policy's `final-allow` trust gate (§5 #7 trust) does not transfer — network policy's fail-closed cross-rung tie (#9) already gives deny the edge; symmetric `final` suffices. |
| 2026-09-03 | **Migration hard cutover — no aliases, every workload rewritten in same PR** | Dual-stack = debt; exhaustive §9.2 table + `validate-config` + golden plans pin the cutover; §9.4 error-message convention cites ADR path so a pasted old TOML directly tells the author the next TOML to write. |
