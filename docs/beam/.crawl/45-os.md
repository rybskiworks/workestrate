## Purpose
Operating system-specific functions. The functions in this module are
operating system-specific. Careless use results in programs that only run on a
specific platform; with careful use they can help a program run on most
platforms.

Note: functions raise `badarg` if arguments contain invalid characters per the
"Data Types" section (encoding via `file:native_name_encoding()`; null chars
disallowed; on Unix `=` disallowed in names, on Windows `=` only allowed as the
first char of a name).

## Key functions (exact arities)
- `cmd/1` — `cmd(Command)` ≡ `cmd(Command, #{})`.
- `cmd/2` — `cmd(Command, Options)` (since OTP 20.2.3).
- `env/0` — list of all env vars as `{VarName,Value}` 2-tuples (since OTP 24.0).
- `find_executable/1` — `find_executable(Name)` ≡ `find_executable(Name, Path)` with `Path` = current execution path (PATH on Unix/Windows).
- `find_executable/2` — `find_executable(Name, Path)` returns absolute filename or `false`.
- `getenv/0` — list of all env vars as `"VarName=Value"` strings.
- `getenv/1` — `getenv(VarName)` -> `Value | false`.
- `getenv/2` — `getenv(VarName, DefaultValue)` -> `Value` (since OTP 18.0).
- `getpid/0` — emulator process id as string (Unix: `getpid()` syscall; Windows: `GetCurrentProcessId()`).
- `perf_counter/0` — counter in `perf_counter` time unit (since OTP 19.0).
- `perf_counter/1` — `perf_counter(Unit)` (since OTP 19.0).
- `putenv/2` — `putenv(VarName, Value)` -> `true`.
- `set_signal/2` — `set_signal(Signal, Option)` (since OTP 20.0).
- `system_time/0` — OS system time in native time unit (since OTP 18.0).
- `system_time/1` — `system_time(Unit)` (since OTP 18.0).
- `timestamp/0` — OS system time in `erlang:timestamp()` format.
- `type/0` — `{Osfamily, Osname}` where `Osfamily :: unix | win32`.
- `unsetenv/1` — `unsetenv(VarName)` -> `true` (since OTP R16B03).
- `version/0` — `VersionString | {Major, Minor, Release}`.

### Requested-but-not-present (correction to crawl brief)
- `listenv/0` — does NOT exist. The list-all function is `env/0` (2-tuple form,
  since OTP 24.0) or `getenv/0` (`"VarName=Value"` string form).
- `monotonic_time/0,1` — NOT in the `os` module. Monotonic time lives in
  `erlang:monotonic_time/0,1`. `os` only exposes OS system time
  (`system_time`, `timestamp`), which is explicitly NOT monotonic.
- `locale/0,1` — NOT present in this module (OTP 29.0.2 / kernel 11.0.2).

## getenv/putenv/listenv
- `getenv/0` returns all env vars as `"VarName=Value"` strings. If Unicode
  filename encoding is in effect, strings may contain codepoints > 255.
- `env/0` (since OTP 24.0) returns the same data as `[{VarName, Value}]`
  2-tuples — docs explicitly say "Consider using env/0 for a nicer 2-tuple
  format."
- `getenv/1` returns `Value | false`; `getenv/2` returns `Value` or
  `DefaultValue` (since OTP 18.0).
- `putenv/2` sets a new value; on Unix uses UTF-8 if Unicode filename
  translation is in effect, on Windows uses wide-character interfaces.
- `unsetenv/1` deletes the variable (since OTP R16B03).
- All name/value strings use `file:native_name_encoding()`; null chars
  disallowed; `=` rules differ Unix vs Windows (see Purpose).

## cmd/1,2 + caveats (vs ports)
`cmd/2` "Executes Command in a command shell of the target OS, captures the
standard output and standard error of the command, and returns this result as
a string."

Caveats:
- Buffers ALL output (stdout + stderr) into a single returned string — not
  streaming. For structured/streaming interaction with external programs,
  prefer ports (`erlang:open_port/2` with `{spawn, Command}`) instead.
- Runs in a command shell subprocess (the shell is configurable via the
  `os_cmd_shell` kernel parameter; by default detected at system startup).
- "in some cases, standard output of a command when called from another program
  can differ, compared with the standard output of the command when called
  directly from an OS command shell."
- Options (`os_command_opts()`):
  - `max_size => non_neg_integer() | infinity` — safety cap on returned data
    (since OTP 20.2.3). e.g. `os:cmd("cat /dev/zero", #{ max_size => 20 })`.
  - `exception_on_failure => boolean()` — if `true`, throws an error exception
    on non-zero exit code with reason `{command_failed, ResultBeforeFailure,
    ExitCode}` (since OTP 28.0).
- `Command :: atom() | io_lib:chars()`; null chars disallowed.

## time BIFs (system_time/monotonic_time/perf_counter/timestamp)
Relationship to `erlang:*` time:
- `os:system_time/0` returns OS system time in native time unit; "This time is
  not a monotonically increasing time." (since OTP 18.0).
- `os:system_time/1` ≡ `erlang:convert_time_unit(os:system_time(), native, Unit)`.
- `os:timestamp/0` returns OS system time "in the same format as
  `erlang:timestamp/0`" — a `{MegaSecs, Secs, MicroSecs}` tuple usable with
  `calendar:now_to_universal_time/1` / `now_to_local_time/1`. "OS system time
  can also be retrieved by system_time/0 and system_time/1."
- `os:perf_counter/0` returns the perf counter in `perf_counter` time unit;
  "highly optimized call that might not be traceable" (since OTP 19.0).
- `os:perf_counter/1` reads directly from hardware/OS; "two consecutive calls
  ... are not guaranteed to be monotonic, though it most likely will be."
- Monotonic time is NOT here: use `erlang:monotonic_time/0,1` for a guaranteed
  monotonic, Erlang-VM-internal time source. `os` time BIFs reflect the OS wall
  clock / hardware counter, which can jump.
- `erlang:time_unit()` is the shared type for `Unit` args across
  `system_time/1` and `perf_counter/1`.

## Strict rules
- All args must be valid per `file:native_name_encoding()`; null chars (0)
  disallowed everywhere. `badarg` raised otherwise.
- Env var names: on Unix `=` disallowed; on Windows `=` only as first char.
- `type/0`: "Think twice before using this function. Use module filename if
  you want to inspect or build filenames in a portable way. Avoid matching on
  atom Osname."
- `version/0`: "Think twice before using this function. If you still need to
  use it, always call os:type() first."
- `system_time/0,1`: explicitly NOT monotonic — do not use for measuring
  intervals; use `erlang:monotonic_time` or `os:perf_counter` instead.
- `perf_counter/1`: not guaranteed monotonic across consecutive calls.
